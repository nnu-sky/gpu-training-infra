# 基线与定位

## 启动前

1. 读取项目说明、规则、训练入口、配置和已有日志，优先复用项目已经验证的命令与环境。
2. 了解模型、数据、精度、批量、GPU 数量、随机种子和当前输出位置；只记录本次比较真正需要的信息。
3. 查看 GPU、CPU、内存、存储和其他任务造成的资源争用，不把明显受干扰的结果当成稳定结论。
4. 区分训练流程、训练期间调用的样本选择或状态更新，以及独立测试和最终评价。后两者只有在训练优化完成后才考虑。

## 轻量基线

优先从已有日志获得时间、吞吐、显存和指标。信息不足时，再运行能够代表当前训练行为的短窗口。

根据项目情况记录：

- 实际命令、代码版本和主要配置；
- 预热后的步耗时、样本吞吐或单轮时间；
- 峰值显存和大致 GPU 利用情况；
- 数据等待、计算、通信、同步和周期性任务中明显的开销；
- 编译、缓存、工作进程启动、尾批和保存是否进入测量窗口；
- 一个最低限度的正确性信号，例如输出范围、损失或项目已有指标。

不要求每个项目收集全部字段。前后对照保持相同工作量和大致相同环境即可；收益接近波动时再补测。

## 观察训练周期

先按代码的真实执行顺序理解一个训练周期，再决定是否需要更细计时。可以从以下层次逐步缩小范围：

1. 启动与初始化；
2. 数据读取、预处理和传输；
3. 前向、方法专属计算、反向和参数更新；
4. 训练期间的样本选择、状态更新、通信、日志和保存；
5. 独立测试与最终评价。

轻量计时已经足以解释问题时，不必使用更重的性能分析器。只有仍存在明显而无法解释的开销时，才对少量稳定步骤使用设备事件、框架性能分析器或系统工具。

## 常见现象

| 现象 | 优先理解 |
| --- | --- |
| GPU 利用率低且数据等待明显 | 读取、解码、变换、缓存、工作进程和主机到设备传输 |
| GPU 利用率高但单步仍慢 | 计算精度、算子、形状、内存访问、编译和方法专属计算 |
| 显存高且吞吐低 | 激活、临时张量、批量、优化器状态和重复保存 |
| 多卡提升有限 | 每卡工作量、通信、数据分片、进程映射和负载不均衡 |
| 周期性停顿 | 样本选择、状态更新、日志、检查点、同步和工作进程重启 |

这些现象只用于缩小搜索范围，不是固定诊断答案。

## 可选状态快照

从技能目录运行 `scripts/capture-training-baseline.sh [采样秒数]` 可以查看 GPU 型号、显存、计算进程和短时利用率。脚本只提供状态快照，不能替代项目内计时。

完成一轮常规优化后重新观察训练周期，确认等待是否转移，并为项目专项探索提供线索。
