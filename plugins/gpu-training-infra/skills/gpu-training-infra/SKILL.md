# GPU 训练性能优化

## 原则

- 先理解并检查整条执行链，再深入项目特有路径；不把寻找最大热点作为启动条件。
- 同时维护两类候选：覆盖多个环节的基础或全局改进，以及来自剖析和项目特有路径的专项改进。
- 以端到端墙钟为主指标，局部加速只有影响总耗时才有价值。
- 验证强度与语义风险匹配，不为每个改动机械运行训练步骤。
- 默认只做短时检查和短基准。除非用户明确要求，不启动完整训练。

## 流程

1. 读取项目规则、训练入口、配置和已有日志，确认允许改动、可比指标、测量窗口与产物位置。
2. 做低成本基础检查：确认实际命令、环境和资源健康，理解从输入到计算、通信、同步和产物写出的真实执行链。检查各环节是否存在可处理开销，不预设瓶颈，也不机械执行固定清单。
3. 先从基础检查中筛选低风险、可能跨多个环节累积生效的改进，并用已有日志或小型组件基准快速判断价值。
4. 按项目真实执行结构建立或复用短基线和时间分解。既有基线只有覆盖同一训练入口和方法专属路径时才能复用，否则只算链路检查。
5. 再审查项目特有执行路径，把主要耗时继续向下拆分，形成可证伪的专项优化判断；任务可清晰拆分时由只读子代理审查互不重叠的路径。
6. 统一维护基础或全局候选与专项候选，按预期端到端收益、可优化余量、语义风险和维护成本选择下一项。需要测量和验收细节时读取 [性能工作手册](references/performance-playbook.md)。
7. 一次验证一个主要改动并按风险分级：已证明不改变训练状态、控制路径和样本选择的等价改动，可用组件数值对照与局部计时验收；可能影响训练轨迹的改动才运行少量训练步。两类都记录速度、显存和必要的正确性指标。
8. 将有价值的单项组合后测量端到端累计收益，再重新检查执行链和项目特有路径；累计收益进入噪声、风险大于收益或维护成本不再值得时停止。

## 交付

报告基线、热点的证据等级、改动机制、各步单项收益、累计最佳组合收益、显存和正确性变化、拒绝项及停止理由。明确区分已证明热点、候选热点和证据不足；不得把某个项目的实现细节写成其他项目的默认答案。
